## Key Decisions

- **Ledger evidence is derived and non-authoritative:** finalized SUMMARY module reports remain source evidence; the ledger is a warm discovery aid and never controls lifecycle routing.
- **UNIFY owns routine ledger appends:** modules, helpers, adapters, and presentation packets do not write efficacy rows or assess their own value.
- **Configuration remains human-gated:** aggregate counts support review but never auto-disable or demote modules; WALT/DEAN/TODD/SETH retain their scoped exemptions.
- **Retroactive extraction never infers action or value:** `Actioned? = yes` requires trace evidence; unmapped statuses and unknown modules remain manifest evidence rather than guessed rows.
- **Absence and unreadable evidence are different findings:** report-bearing units in unsupported shapes use `unrecognized-dispatch-shape`, not `no-dispatch-evidence`.
- **Read-only guarantees require path-set evidence:** all boundary checks precede directory creation, and tests compare complete path sets rather than file hashes alone.
- **Roll-ups derive only from committed normalized artifacts:** re-parsing source SUMMARYs during aggregation would create a competing normalization path.
- **Proposals remain proposed-only:** normalized counts aid discovery, but source SUMMARY interpretation and explicit human approval govern any future implementation.

## Patterns Established

- Use normalized harvest rows for discovery, then return to authoritative source SUMMARYs for interpretation.
- Cross-check retrospective parsers against independently produced forward-path output before trusting them at scale.
- Write aggregate contracts and hand-authored goldens before implementing generators.
- Keep bounded decision logic in sourceable helpers while official callers retain TAP ownership.
- Render absent observations as `—`, never as measured zero.
- Guard proposal completeness dynamically from committed evidence keys rather than duplicating the key set in shell.
