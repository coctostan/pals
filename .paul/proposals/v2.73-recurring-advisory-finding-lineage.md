# Recurring Advisory Finding Lineage

## Evidence

Hybrid-energy-reasoner Phase 02 through Phase 06 each recorded the same DAVE condition: no CI configuration, explicitly deferred outside the active feature phase (`02-01-SUMMARY.md:74,143`; `03-01-SUMMARY.md:77,148`; `04-01-SUMMARY.md:81`; `05-01-SUMMARY.md:77,149`; `06-01-SUMMARY.md:37,139`). Phase 16 later added `.github/workflows/ci.yml` and CI contract tests (`16-01-SUMMARY.md:9,21-23,43-45`).

The five normalized WARN rows are useful lineage evidence, but they are not five independent demonstrations of value. The source shows one persistent finding repeated across phases and eventually resolved by a separately approved plan.

## Problem

Human proposal analysis currently has to infer when repeated rows describe one finding identity, a materially changed recurrence, or unrelated observations. Treating recurrence as independent evidence overstates support; collapsing it without provenance hides persistence and eventual resolution.

## Proposed Change

During human proposal analysis, allow a batch to assign a stable, source-cited lineage identity to repeated findings and record:

- first observation and later recurrences;
- material wording/scope changes;
- explicit deferrals;
- source-backed resolution, if any;
- why recurrence changes or does not change the recommendation.

Keep lineage in proposal-analysis artifacts by default. A future approved plan may define a bounded optional representation only if real use demonstrates the need.

## Non-Goals

- No default expansion of the five-column Module Efficacy Ledger schema.
- No telemetry or background collection.
- No automatic escalation, ranking, lifecycle mutation, or proposal creation.
- No claim that recurrence measures module value or action effectiveness.
- No retroactive source SUMMARY or harvested-ledger edits.

## Risks

- Over-broad identity matching could collapse distinct findings.
- Text similarity could be mistaken for semantic identity.
- A lineage field could become de facto telemetry if generated automatically.
- Resolution claims could be wrong unless tied to explicit source evidence.

## Validation Shape

If humans approve a future implementation plan, start contract-first with hand-written fixtures for same finding/same scope, same wording/different scope, explicit resolution, and unresolved recurrence. Require source citations and mutation tests proving distinct findings are not merged. Keep any output derived and non-authoritative.

## Human Route

A framework maintainer should choose reject, defer, or authorize a normal discussion/PLAN for a proposal-analysis lineage contract. Approval of this document alone does not authorize implementation.
